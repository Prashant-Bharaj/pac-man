# Pac-Man — Ghosts! More ghosts!

A complete recreation of the classic 1980 arcade game Pac-Man, built in Python with a modular OOP architecture, pygame graphics, and external maze generation.

---

## Description

Navigate Pac-Man through procedurally generated mazes, eating pacgums and avoiding ghosts. Eat a super-pacgum to turn the tables — ghosts become edible for a short time. Clear all pacgums to advance to the next level. The game features a persistent highscore system, a full graphical UI, and a cheat mode for evaluation.

## Configuration

The game is configured via a JSON file passed as a command-line argument:

```bash
uv run python pac-man.py config.json
```

The config file supports `#` and `//` comment lines (stripped before parsing). All keys are optional — missing or invalid values fall back to safe defaults without crashing.

### Keys

| Key | Default | Description |
|-----|---------|-------------|
| `highscore_filename` | `"highscores.json"` | Path to the highscore storage file |
| `lives` | `3` | Starting lives (clamped to 1–99) |
| `pacgum` | `42` | Number of pacgums per level |
| `points_per_pacgum` | `10` | Score for eating a pacgum |
| `points_per_super_pacgum` | `50` | Score for eating a super-pacgum |
| `points_per_ghost` | `200` | Score for eating an edible ghost |
| `seed` | `42` | RNG seed used for level 1 maze |
| `level_max_time` | `90` | Time limit per level in seconds (clamped to 10–3600) |
| `levels` | 10 default levels | Array of per-level configs (`width`, `height`, `seed`) |

### Example

```json
{
  # Starting lives
  "lives": 3,
  "points_per_pacgum": 10,
  "points_per_super_pacgum": 50,
  "points_per_ghost": 200,
  "seed": 42,
  "level_max_time": 90,
  "highscore_filename": "highscores.json",
  "levels": [
    { "width": 20, "height": 20, "seed": 42 },
    { "width": 21, "height": 21 }
  ]
}
```

## Highscore

Highscores are stored in a JSON file on disk (path set by `highscore_filename` in config, default `highscores.json`).

**Why JSON file storage:** simple, portable, human-readable, and requires no external database dependency — fits the project's self-contained deployment requirement.

**Rules:**
- Top 10 scores are kept, sorted by score descending.
- Player names: max 10 characters, alphanumeric and spaces only.
- Scores: non-negative integers.
- Loaded at game start; saved when a game ends (win or lose).
- Robust to missing or corrupt files — starts fresh without crashing.

## Maze Generation

Mazes are generated by an externally assigned *A-Maze-ing* package (not written by us). The package is used as-is via a thin adapter in `src/maze.py`.

- **Level 1** uses a fixed seed (from config, default `42`) for a reproducible first level.
- **Subsequent levels** use incrementing seeds for variety.
- `PERFECT=False` is passed to produce Pac-Man-compatible looping corridors.
- If the generator raises any exception, `src/maze.py` falls back to a minimal valid open maze and logs an error — the game continues.

## Technical Choices

### Pydantic vs Dataclasses

The project uses both, each where it fits best.

| | `dataclasses` | `pydantic` |
|---|---|---|
| Validation | None built-in | Built-in, rich |
| Type coercion | None | Automatic |
| Error messages | You write them | Detailed, automatic |
| Performance | Faster | Slight overhead per construction |
| Dependency | stdlib | External |
| Serialization | Manual | `.model_dump()` / `.model_validate()` built-in |

**Pydantic** is used for `GameConfig` and `LevelConfig` because config files are untrusted external input — wrong types, missing keys, and out-of-range values are all expected. Pydantic handles this declaratively: `Field(ge=1, le=99)` documents and enforces the valid range in one place, `model_config = {"extra": "ignore"}` silently drops unknown keys, and `model_validate(dict)` parses directly from the JSON dict without manual key unpacking.

**Dataclasses** are used for game entities (`Player`, `Ghost`, `Pellet`) because they are constructed by trusted internal code, never parsed from external input. Pydantic's validation overhead on every object creation inside a game loop would be wasteful.

## Implementation

### Phase 1 (complete)

- **Project scaffold** — `pyproject.toml` with `uv`, `Makefile` with all required targets, `.gitignore`, `.flake8` config.
- **Config loader** (`src/config.py`) — Pydantic v2 models (`LevelConfig`, `GameConfig`) with `@field_validator` for clamping, `model_config = {"extra": "ignore"}` for unknown keys, and `#`/`//` comment stripping before JSON parsing. Never raises on bad input.
- **Entity stubs** — `Player`, `Ghost` (with `CHASE`/`EDIBLE`/`RESPAWNING` state machine), `Pellet` (pacgum / super-pacgum).
- **Highscore system** (`src/highscore.py`) — `load`, `save`, `add_entry` functions; validates names and scores; keeps top 10.
- **Level stub** (`src/level.py`) — places player at maze centre, ghosts at corners, pellets in all corridors.
- **Game state machine stub** (`src/game.py`) — `MAIN_MENU → PLAYING → PAUSED → GAME_OVER / VICTORY → NAME_ENTRY → MAIN_MENU`.
- **Cheat mode stub** (`src/cheat.py`) — invincibility, ghost freeze, speed boost toggles.
- **UI stubs** — `MainMenu`, `HUD`, `PauseMenu`, `GameOverScreen`, `VictoryScreen`.
- **Maze adapter stub** (`src/maze.py`) — wraps A-Maze-ing package with fallback.
- **Test suite** — 17 tests covering config loading and highscore logic.

## General Software Architecture

```
pac-man.py                  # Entry point — parses args, loads config, starts Game
│
├── src/config.py           # Pydantic models: GameConfig, LevelConfig
│                           # load_config() — strips comments, validates, clamps
│
├── src/game.py             # Game — state machine, main loop (pygame)
│   ├── src/level.py        # Level — maze + entity placement per level
│   ├── src/renderer.py     # Renderer — all pygame draw calls
│   ├── src/cheat.py        # CheatMode — toggleable cheat flags
│   └── src/ui/             # Screen classes (menu, hud, pause, gameover, victory)
│
├── src/entities/
│   ├── player.py           # Player — movement, lives, score
│   ├── ghost.py            # Ghost — AI state machine (chase/edible/respawn)
│   └── pellet.py           # Pellet — pacgum and super-pacgum
│
├── src/maze.py             # Adapter for the A-Maze-ing package → MazeGrid
├── src/highscore.py        # load / save / add_entry — top-10 JSON persistence
│
└── tests/
    ├── test_config.py      # Config loader: valid, missing, corrupt, clamping
    └── test_highscore.py   # Highscore: CRUD, validation, persistence
```
